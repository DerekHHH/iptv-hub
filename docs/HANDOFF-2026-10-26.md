## 3. 迁移到红米的方案

> 目标：红米常开，家里电视/手机都能看。**关键差异是基址** —— 红米有局域网 IP，产物要写它，电视才播得了。

### 步骤

```bash
# ① 先体检（只读，不改任何东西）
bash /data/local/tmp/preflight.sh
cat /sdcard/preflight.txt
```

体检报告重点看三处：
- `Wi-Fi IP` → 后面 `WUDALIANSAI_PUBLIC_BASE` 要用它
- `--- 7. 旧机制还在不在 ---` → 旧看门狗必须停掉（见下）
- `~/.local/wudaliansai` 是**目录还是文件** → 历史事故点

```bash
# ② 停掉 10-24 那套旧机制（否则它会杀掉我们的网页服务）
pkill -f '[s]cripts/watchdog.sh'
mkdir -p ~/.local/state/iptv-hub
echo on > ~/.local/state/iptv-hub/web.state
echo on > ~/.local/state/iptv-hub/live.state
```

> **为什么必须停**：`scripts/watchdog.sh` 按 `web.state` 管理网页服务，state 是 `off` 时它会**不停杀掉** serve.mjs。
> 现象很坑：服务打印「已启动」后凭空消失，退出码 143（SIGTERM），日志里没有任何报错。

```bash
# ③ 拉最新代码
cd ~/iptv-hub
git fetch origin && git reset --hard origin/main
git log --oneline -1        # 确认拉到今天的提交（看有没有 tvg-name / 黑名单相关）

# ④ 装新开关与看门狗
bash scripts/android/setup-phone.sh

# ⑤ 用「局域网基址」重建（这样电视也能播）
WIFI_IP=$(ip -4 addr show wlan0 | grep -oE 'inet ([0-9.]+)' | awk '{print $2}' | head -1)
```

## 4. 十条踩坑（这些最值钱，别再踩一遍）

1. **m3u 必须带 `tvg-name`** —— 影视仓/TVBox 靠它建频道名，缺了解析出 0 个频道，现象是"加载失败"且连续重试几次，服务端看起来一切正常。
2. **影视仓「配置地址」要 JSON，不是 m3u** —— 填 m3u 必然解析失败。
3. **SELinux 禁止 Termux 执行 `/data/local/tmp` 的二进制** —— 权限位 755 也没用，必须 `cp` 进 Termux 家目录。
4. **`~/.local/wudaliansai` 可能是同名目录**（历史遗留）→ `cp` 会把文件塞进目录里，而 `[ -x 目录 ]` 也返回 true。必须 `[ -f ] && [ -x ]`。
5. **`/data/local/tmp` 对 Termux 只读** → 日志重定向会 `Permission denied` 导致进程起不来。
6. **判活只能用端口**，不能用 `pgrep` —— Android 的 /proc 隔离让 Termux 看不到别的 uid 的进程，会误判成"没在跑"然后重复启动撞 EADDRINUSE。
7. **`pgrep -f wdl-watchdog.sh` 会匹配到自己** —— 改用 `pgrep -f '[w]dl-watchdog'`。
8. **`adb shell "... &"` 会被后台子进程拖住不返回** —— 写成 `( cmd </dev/null >/dev/null 2>&1 & ); exit 0`。
9. **Node 的 fetch 不认 `http_proxy`** —— 本机跑 `build:live` 要加 `NODE_OPTIONS=--use-env-proxy`；手机直连不需要。
10. **手机端 `git fetch` 会静默失败** —— `reset --hard origin/main` 停在旧提交。急着验证就直接 `adb push` 文件覆盖，别等 git。

### 分类的两个教训（业务层）

- **短关键词做包含匹配必然串联赛**：`勇士`/`雷霆`/`开拓者` 会命中日本、菲律宾的队。
  靠"关键词更长者优先"救不了 —— 真正的解法是**先排外国联赛黑名单**。
- **上游的后缀不都是状态**：`|高清`、`|赛场原声` 是**线路名**，只有 `|完场`/`|未开赛`/`|暂无直播` 才是状态。
  把"没有状态后缀"当成"正在直播"是错的（实测 CBA 还没开打就被标了 `[比赛中]`）。

## 6. 给家里 WorkBuddy 的排查三步法

遇到「加载失败/超时」，**按顺序**排查，别跳步：

```bash
# 第一步：服务活着吗（端口 + 进程）
/system/bin/nc -z -w 2 127.0.0.1 18765 && /system/bin/nc -z -w 2 127.0.0.1 18080

# 第二步：内容对吗（长度 + 关键字段）
curl -sS http://127.0.0.1:18080/live/live.m3u | wc -c
curl -sS http://127.0.0.1:18080/live/live.m3u | sed -n '2p' | grep -c tvg-name
grep -ohE 'http://[0-9.]+:[0-9]+' ~/iptv-hub/dist/live/live.txt | sort -u

# 第三步：请求真的进来了吗（看服务端日志）
grep '\[serve\] 20' ~/.local/serve.log | tail -10
#   → 有 okhttp/xxx 的请求 = 客户端连上了，问题在内容格式
#   → 一条都没有     = 地址错 / 服务没起 / 被系统拦
```

**教训**：用户说"还是不行"时，先做**服务端全链路实测**（字节数 + 内容 + 跳转），
确认服务没问题后再怀疑客户端。今天在这上面来回浪费了四轮。
