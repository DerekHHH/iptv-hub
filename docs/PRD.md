# PRD：纯 GitHub 托管 IPTV 电视源工具

## 1. 项目信息

| 项 | 值 |
|---|---|
| Language | 简体中文 |
| Programming Language | TypeScript + Node.js（脚本/测活引擎）；Vite + React + MUI + Tailwind CSS（网页端）；运行载体 = GitHub Actions + GitHub Pages |
| Project Name | `iptv_source_hub` |
| 交付形态 | 零服务器、零费用的公开 GitHub 仓库（Actions 构建 + Pages 分发） |

**原始需求复述**：家里电视要看直播台，网上找的 IPTV 源几天就失效，手动整理 m3u 太累，又不想买服务器。希望有一个工具，能自动抓取公开源、自动测活优选、生成电视端可直接导入的播放列表，放在固定链接上，电视配置一次长期可用；源失效时列表自动更新。

---

## 2. 产品定义

### 2.1 产品定位（一句话）

> 一个"配一次、长期不用管"的 IPTV 电视源聚合与自愈工具：GitHub 自动抓源、测活、优选、出列表，电视端只认一个固定链接。

### 2.2 产品目标

| # | 目标 | 衡量标准（可验证） |
|---|---|---|
| G1 | 电视端导入即可用 | 生成的 TXT 列表中，**可用频道数 ≥ 60**，其中港澳台 + 广东本地 ≥ 25 |
| G2 | 单频道多源冗余有效 | 每频道保留 3 个源时，**至少 1 个源存活的频道占比 ≥ 90%** |
| G3 | 无人值守自动保鲜 | Actions 每 6 小时成功运行率 ≥ 95%（30 天窗口），产物 `updated_at` 与最近运行时间差 ≤ 7 小时 |
| G4 | 非技术用户可自助上线 | 新用户按《使用说明》从 Fork 到电视可用 **≤ 20 分钟**，无需命令行 |
| G5 | 上游故障不炸列表 | 单次构建中上游抓取失败率 ≥ 50% 时，**不发布空/劣化列表**，沿用上一次产物并标注 stale |

### 2.3 目标用户与场景

| 用户 | 特征 | 关键约束 |
|---|---|---|
| 个人用户（主） | 广东地区，自家电视/投影，非技术背景 | 不会写代码、不买服务器、不愿付费 |
| 家庭用户（次） | 为父母/长辈配置电视 | 配置一次后不能反复维护；长辈只会开机换台 |

**核心场景**：电视装 DIYP / 影视仓 / TVBox 类播放器 → 粘贴一个固定 TXT 链接 → 看直播。列表半年不动，源自动更新。

## 3. 用户故事

| ID | 角色 | 我想要 | 以便于 |
|---|---|---|---|
| US-1 首次接入 | 非技术用户 | Fork 仓库 → 打开 Pages 首页照教程点几下就拿到 TXT 链接 | 5 分钟内在电视上看到第一个频道 |
| US-2 日常观看 | 家庭用户 | 打开电视就是能播的台，港澳台和广东台排在最前 | 不用记频道号、不用天天折腾 |
| US-3 源失效自愈 | 个人用户 | 某个源挂了下次自动换掉，我什么都不用做 | 列表长期可用，无需重新配置电视 |
| US-4 手动触发更新 | 个人用户 | 在网页上点一个按钮就能立刻重新构建（不装任何环境） | 着急看某个台时不用等到下一个 6 小时周期 |
| US-5 临时测源 | 个人用户 | 在网页里粘贴一段源文本，立刻看到哪些能用、延迟多少 | 判断自己找到的源值不值得加进来 |

## 4. 需求池

### P0（Must have，缺一不可）

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-1 | 公开源自动抓取 | 从 ≥3 个公开 GitHub 源（iptv-org 等）拉取原始列表；GitHub Raw / jsDelivr 双通道兜底；每次构建记录各源抓取成功/失败与条目数 |
| P0-2 | 频道名规范化与去重 | 同频道多写法（"CCTV1/CCTV-1/中央1台"）归一为一个标准名；输出列表中**频道名唯一**，无重复行；归一规则以配置表驱动，可扩展 |
| P0-3 | 并发测活 | 对全部候选源并发探测（默认并发 64，可配）；判定依据 = TCP/HTTP 连通 + 收到有效流数据；单源超时 ≤ 8s；记录延迟(ms)、分辨率、码率（能取到时） |
| P0-4 | 每频道优选 3 源 | 按「分辨率降序 → 延迟升序」排序取前 3；存活源不足 3 个时**保留实际存活数**（≥1 才输出该频道），不以死链凑数 |
| P0-5 | TXT 生成 | 路径 `dist/txt/all.txt`；分组头 `频道名,#genre#`；每频道一行 `频道名,url1#url2#url3`；UTF-8 无 BOM；符合 DIYP/影视仓/TVBox 解析规则 |
| P0-6 | M3U 生成 | 路径 `dist/m3u/all.m3u`；`#EXTM3U` 头 + 每源一条 `#EXTINF:-1 tvg-name="..." group-title="...",频道名`；UTF-8 |
| P0-7 | EPG 生成 | 路径 `dist/epg/epg.xml`；符合 XMLTV 标准（`<tv>` / `<channel>` / `<programme start stop channel>`）；时间戳格式 `YYYYMMDDHHmmss +0800`；**EPG 失效不影响列表产出**（失败仅跳过并告警） |
| P0-8 | Actions 定时每 6 小时 | `.github/workflows/update.yml`，`schedule: cron '0 */6 * * *'` + `workflow_dispatch`；可从 Actions 页面手动 Run |
| P0-9 | GitHub Pages 发布 | 产物发布到 Pages，固定 URL 可访问；同时提供 raw.githubusercontent 直链与 jsDelivr 镜像两套链接 |
| P0-10 | 网页测活台 | 粘贴或上传源文本 → 点击检测 → 表格展示（频道名/源地址/状态/延迟/分辨率/码率）；支持按列排序与状态筛选；支持"一键复制可用源"与"导出 txt"；**纯浏览器内运行，无需安装环境** |
| P0-11 | 一键更新按钮 | 输入免费 GitHub PAT（存 localStorage）→ 校验权限 → 调 `workflow_dispatch` 触发构建 → 轮询显示运行状态与日志链接 → 完成后刷新产物；Token 显示掩码，可一键清除 |
| P0-12 | 使用说明文档 | 首页内嵌图文分步教程（Fork → 开 Pages → 生成 Token → 粘贴到电视）＋ 常见播放器（DIYP/影视仓/TVBox）配置入口截图级说明；**不出现未解释的技术名词** |
| P0-13 | 上游降级 | 抓取失败率 ≥50% 或候选源总数低于阈值时，**不覆盖**上一版产物；首页显示"数据为上次构建（时间）"警示 |
| P0-14 | 构建看板数据 | 每次构建生成 `dist/stats.json`（频道数、源数、更新时间、各分组数量、构建耗时），首页读取并展示 |

### P1（Should have）

| ID | 需求 | 验收标准 |
|---|---|---|
| P1-1 | 频道分组优化 | 分组顺序固定为：港澳台 → 广东本地 → 央视 → 卫视 → 其他；组内按频道台号/名称排序 |
| P1-2 | 重点频道置顶 | 港澳台 + 广东频道位于 TXT 文件前两个 `#genre#` 分组（电视端首屏可见） |
| P1-3 | 失效源黑名单记忆 | 连续 2 次构建均判定失效的 URL 进入 `blacklist.json` 并在后续构建中降权/跳过；黑名单命中但再次测活成功的可恢复 |
| P1-4 | 测活历史 | 保留最近 7 次构建的存活率/频道数趋势，首页以折线或表格展示 |
| P1-5 | 频道图标 | M3U 输出 `tvg-logo`，缺失时留空不报错 |

### P2（Nice to have）

| ID | 需求 | 验收标准 |
|---|---|---|
| P2-1 | 自建源手动追加 | 仓库根 `custom/sources.txt` 用户自填行被合并进候选池，且优先级高于自动抓取 |
| P2-2 | 多套列表 | 额外产出 `lite.txt`（仅港澳台+广东+央视）与 `all.txt`（全量） |
| P2-3 | 频道别名自定义 | 配置文件支持自定义频道名映射，改完下次构建生效 |

## 6. 产物规范

| 产物 | 路径 | 格式要点 |
|---|---|---|
| TXT（主） | `dist/txt/all.txt` | 分组头 `频道名,#genre#` 单独成行；频道行 `频道名,url1#url2#url3`；空行分隔组；UTF-8 无 BOM；**仅输出存活源** |
| M3U | `dist/m3u/all.m3u` | 首行 `#EXTM3U`；每源 `#EXTINF:-1 tvg-name="标准频道名" tvg-logo="..." group-title="港澳台",标准频道名` + 下一行 URL |
| EPG | `dist/epg/epg.xml` | `<tv>` 根节点；`<channel id>` 与 M3U `tvg-name` 对应；`<programme start="20250101120000 +0800" stop="..." channel="...">` + `<title>` |
| 统计 | `dist/stats.json` | `{updated_at, channel_count, source_count, groups:{...}, build_duration_ms, stale:boolean}` |
| 黑名单 | `data/blacklist.json` | `{url: {fail_count, last_checked}}` |
| 发布 | Pages + `raw.githubusercontent.com` + `cdn.jsdelivr.net` | 三套链接均写入首页，同一产物 |

**排序规则**：分组顺序 港澳台 → 广东 → 央视 → 卫视 → 其他；组内频道名按拼音/台号升序；每频道源按（分辨率降序，延迟升序）。

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 构建时长 | 单次 Actions 构建 **≤ 25 分钟**（GitHub 免费额度上限 6h，留足余量）；超时前必须已写出上一版产物 |
| 并发控制 | 测活并发默认 64，可配；Actions 内 workflow 加 `concurrency` 组，同一分支不并发运行，避免产物互相覆盖 |
| 抓取容错 | 每个上游独立 try/catch + 双通道（raw / jsDelivr）重试；单上游失败不阻断整体 |
| 降级策略 | 候选源 < 阈值 或 抓取失败率 ≥50% 或 输出频道数 < 上次的 60% → **不发布**，保留旧产物，`stats.json` 标 `stale=true`，首页黄条提示 |
| 仓库体积 | 产物总量 ≤ 20 MB；不提交原始抓取缓存；`.gitignore` 排除临时文件；历史产物不累积（覆盖式提交） |
| 兼容性 | 网页端支持 Chrome/Safari 最新两个大版本、iOS Safari、以及**电视端内置浏览器（Android WebView）**；响应式 ≥ 360px 宽可用；无 JS 构建期依赖的阻塞性 CDN |
| 隐私安全 | Token 仅 localStorage；代码中无任何上报/统计请求；测活台纯前端，源文本不出浏览器 |
| 可维护性 | 频道归一映射、分组规则、阈值全部走配置文件，改配置无需改代码 |

## 8. 风险与免责

| 风险 | 影响 | 应对 |
|---|---|---|
| 公开源版权 | 法律风险 | 产物首页与仓库 README 明确：所有流媒体版权归各广播机构所有，本项目仅做公开链接的技术聚合与可用性探测，不存储、不转码、不分发内容 |
| 源可用性波动 | 用户预期落差 | 明确"不保证任何频道长期可用"；以多源冗余 + 6 小时自动更新缓解 |
| 上游仓库失效/改名 | 列表变空 | 多上游 + 降级策略 + 黑名单，绝不发布空列表 |
| GitHub Token 泄露 | 账号风险 | 仅存 localStorage、仅申请 `workflow` 最小权限、文档强调"像密码一样对待"、支持一键清除；README 提示可用 Fine-grained Token 限定单仓库 |
| Actions 免费额度 | 构建被限流 | 6 小时一次（约 4 次/天）；公开仓库 Actions 免费；单次控制在 25 分钟内 |
| 电视端播放器差异 | 导入失败 | 同时提供 TXT + M3U，教程覆盖 DIYP / 影视仓 / TVBox 三类 |
